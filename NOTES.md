# Photo Journal — implementation notes

I spent about four hours on the exercise. I built the required feed, detail, and upload flows first, then added photo interactions and offline viewing. The one feature from the original README that I left out is resuming an upload after the app is killed; I reached the time limit before I could make the active queue durable.

The app shares its Compose screens and ViewModels between Android and iOS. Each screen exposes a state object and receives actions, which keeps loading, errors, retry, and navigation in one place. I separated domain models and upload rules from the fake API and Room. Repositories translate between them, and Koin supplies the implementations. `PrepareUploadUseCase` checks for duplicates and reserves a stable client upload ID; `UploadPhotoUseCase` handles progress and records completion. Duplicate detection uses SHA-256 of the selected bytes. It recognizes the same file across launches, but not a visually identical photo that has been re-encoded.

Room stores completed uploads and the photo details needed to show history after relaunch. It also keeps a snapshot of fetched feed photos. Coil stores images that have actually loaded in its disk cache. Together, these let the app reopen previously viewed images without a connection. Images that were never loaded still need the network, and the operating system may eventually clear the cache. I kept upload history local because the supplied fake API forgets uploads when its process ends.

The photo UI, upload flow, design system, and detail gestures stay shared. Android uses a large left-aligned header, system back, and the Android photo picker. iOS uses a centered title, blue text actions, “Done,” and PHPicker. I chose the system pickers so selection feels familiar and needs no broad photo-library permission. Small platform implementations provide those controls and the detail status-bar appearance. Both platforms draw edge-to-edge. The detail view supports pinch zoom, paging, a shared transition, swipe dismissal, and thumbnail-first loading.

For a production version, I would persist a bounded copy of each selected file and its queue state, then use platform background transfer APIs to resume interrupted uploads. I would also define a deliberate image-retention policy, show when the app is offline, and run more device-level checks.

I used AI coding assistance for implementation and review. The output was checked with Android and iOS builds, Android host tests for duplicate detection, persistence and migration, and an Android emulator check: previously loaded grid images remained visible after relaunch with Wi-Fi and mobile data off. The iOS app builds in Xcode, but a final iOS simulator walkthrough is still pending. The submission screen recordings are also still to be captured.
